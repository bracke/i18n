# i18n

`i18n` is a native Ada 2022 **Unicode/CLDR internationalization platform**: a
strict, deterministic implementation of the Unicode text algorithms and the CLDR
formatting, names, and data stack. It has no external runtime dependencies and
generates its locale data from a checked, pinned CLDR/tzdb subset.

ICU-style **message formatting** (catalogs, `{count, plural, …}` rendering) is
**not** part of this crate — it lives in the sibling
[`messages`](../messages) crate, which depends on this one.

## What the platform provides

**Unicode text algorithms**

* `I18N.Normalization` — NFC / NFD / NFKC / NFKD (UAX #15)
* `I18N.Casing` — lower / upper / title with SpecialCasing
* `I18N.Segmentation` — grapheme / word / sentence / line boundaries (UAX #29 / #14)
* `I18N.Collation` — UCA sort keys, comparison, and locale tailoring
* `I18N.Transliteration` — the CLDR transform rule engine (contexts, calls, sets)

**CLDR formatting, names, and data**

* `I18N.Number_Format`, `I18N.Currency` — grouped decimals, percent/permille,
  compact/scientific notation, precision and rounding skeletons, currency
  symbols/names/accounting, per-locale digits and grouping
* `I18N.Date_Time_Format`, `I18N.Calendars`, `I18N.Calendar_Math` — styles and
  `::` skeletons, non-Gregorian calendars, tzdb transition offsets and zone display
* `I18N.Spellout` — RBNF number-to-words
* `I18N.Plurals` — CLDR cardinal/ordinal plural categories
* `I18N.Display_Names`, `I18N.Emoji`, `I18N.Measurement`, `I18N.Delimiters`,
  `I18N.Person_Names` — CLDR names, emoji annotations, units, delimiters, TR35 names

**Locale identity and data layer**

* `I18N.Locales` — BCP-47 canonicalization, likely-subtag maximize/minimize,
  language/script/region components, display names, text direction, and bounded
  locale-sensitive case/normalization/transliteration/collation/segmentation helpers
* `I18N.Data_Store`, `I18N.Runtime_Data`, `I18N.CLDR_Data` — the generated-data
  boundary and process-wide deterministic runtime-data overrides

The full, exhaustively-enumerated coverage (scripts, locales, skeletons,
calendars, zones, units) is documented in `docs/API.md` and `docs/ICU_SUBSET.md`.

## Example

```ada
with I18N.Transliteration;  use I18N.Transliteration;
--  ...
S : constant String := Transform ("Ελληνικά", "Greek-Latin");
```

```ada
with I18N.Plurals;
--  I18N.Plurals.Cardinal ("en", 1)  => One
--  I18N.Plurals.Ordinal  ("en", 2)  => Two   ("2nd")
```

## Build and tests

```sh
alr test
```

`alr test` builds and runs the standalone platform suite (`tests/`, rooted at
`I18N.Platform_Tests`): 11 engine tests covering transliteration, collation,
casing, normalization, segmentation, calendar math and names, display names,
emoji annotations, person names, and spellout, exercised against the generated
`share/i18n` data.

## CLDR data pipeline

Locale data is generated, not hand-maintained. `cldr/cldr_tools.gpr` builds
`check_cldr_sources`, `check_tzdb_sources`, `generate_cldr_export`,
`import_cldr_raw`, `extract_cldr_normalized`, `import_cldr_subset`, and
`generate_cldr_data`; their `--check` modes verify the data boundary. The staged
upstream fixture is `cldr/upstream/cldr_export.jsonl` with provenance in
`cldr/upstream/source_manifest.txt`; IANA tzdb fixtures live under
`cldr/upstream/tzdb/`. Formatters consume everything through the generated
`I18N.CLDR_Data` boundary rather than embedding independent copies. The
generated `src/i18n-cldr_data*.adb` bodies are gitignored and regenerated by the
Alire pre-build action (`cldr/regenerate.sh`); see `cldr/CLDR_DATA.md`.
